# Contributing

Thanks for wanting to help. Contributions of any size are welcome, from fixing a typo to adding a new example.

## How to contribute

1. **Pick a task.** Open the **Issues** tab and choose one. Issues labelled `good first issue` are the easiest place to start.
2. **Claim it.** Comment "I'll take this" on the issue so nobody else starts the same work.
3. **Fork the repo.** Click **Fork** at the top right of the repository page. This creates your own copy.
4. **Create a branch** in your fork with a short descriptive name, for example `fix-hardcoded-paths`.
5. **Make your change.** Keep it focused on the one issue.
6. **Open a pull request.** Push your branch and click **Compare & pull request**. In the description, write `Closes #<issue number>` and say briefly what you changed and how you tested it.
7. **Review.** I'll read it, may ask for small changes, and then merge it.

## Guidelines

- One issue per pull request. Small pull requests get merged faster.
- Don't commit generated files: MATLAB `slprj/` folders, `*.slxc`, `*.asv`, or large `*.mat` result files.
- Keep the existing file and folder layout unless the issue asks you to change it.
- If you used code from somewhere else, say where it came from and check that its license allows it.
- If something is unclear, ask in the issue before you start.

## Reporting a problem

Found a bug or something that doesn't run? Open a new issue with what you ran, what you expected, what happened instead, and your MATLAB or Python version.
